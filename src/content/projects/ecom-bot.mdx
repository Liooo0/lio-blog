## 为什么做这个

想跑通无货源电商副业：从 1688 批发市场找货，挂到闲鱼零售赚差价，不囤货不压资金。但选品比价、算利润、写商品文案全是重复劳动；闲鱼风控又严，全自动发布等于送号。我需要一条**半自动流水线**：机器负责找货、算账、写稿，人只做选款和回消息。

## 功能

- **1688 采集** — 移动端搜索页抓商品，随机 UA、限速 5s+、失败重试，不登录不并发不下图（反爬设计）
- **清洗解析** — 价格区间 min/max、销量"万/+"归一、标题去 emoji 和噪音词
- **利润计算** — `成本×1.5+8元` 运费缓冲，可配 markup_rate / floor_price，输出进价/售价/利润/利润率
- **商品库** — SQLite 按商品 ID 去重，支持导出 CSV（全字段+利润）
- **上架草稿** — 闲鱼人话文案（标题/标价可小刀/描述/售后话术），内部备注成本不混入
- **违禁词扫描** — 44 词 BLOCK/WARN 分级（含 vx/微❤ 谐音变体），上架前过滤器
- **自动发布** — 连调试 Chrome 走闲鱼网页版填表发布：传图、描述、价格、地址一键完成

## 技术架构

Python 全流程 + SQLite 存储，浏览器自动化用 DrissionPage（连 9222 调试端口 Chrome，真实浏览器指纹，不被风控识别为脚本）。发布页的坑都是实测踩出来的：描述框是 contenteditable 要用 execCommand 输入、描述禁止 emoji、发布成功看 URL 是否跳商品页。61 个单测守护解析和扫描逻辑。

## 实际效果

- 首批 19 个商品入库，选中 2 款已上线闲鱼：316 马克杯 ¥51、口袋保温杯 ¥65，均包邮
- 全程小号操作，发布节奏人工控制，不碰自动改价/批量操作这些高危动作
- 闲鱼 0.6% 基础服务费已算进定价，利润模型不受影响
- 验证了"机器备料、人做决策"的半自动模式：选款看销量验证 + 利润排序，发布 5 分钟搞定

## 现状

MVP1 完成，正在跑第一批 2 款商品的真实流量数据。下一步根据浏览/咨询数据决定是否扩品，以及做自动回复（保守节奏）。
