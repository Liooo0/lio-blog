## 01 / 背景与痛点（Why）

在落地 AI 应用时，最耗费心力的往往不是写代码，而是模型选型：

1. **公开基准榜单与实际业务脱节**：各大模型的评测跑分再高，也无法直接回答“在我的 Prompt 格式下谁更听话”、“代码评审谁挑刺更准”、“中文长文本谁幻觉更少”。
2. **缺乏单模型故障隔离**：许多多模型评测脚本采用简单的串行调用，只要其中一个模型连接超时，整个评测流程就会中断。
3. **主观体感需要客观数据锚定**：选型不能全凭“感觉这个回复好像好一点”，需要把耗时、首字延迟、单题质量胜负比放在同一个表格里横向对齐。

我需要一个**无外部重量级依赖、能把真实业务考题丢进去并发对比、单模型故障隔离且有完整数据沉淀的实战对战台**。

## 02 / 解决与实现（Built）

我开发了这款轻量级并发竞技系统 LLM Arena：

- **并发对战与故障隔离**：输入一个业务问题，勾选多个目标模型，基于 `asyncio.gather` 并发分发。单个模型遭遇网络抖动或限流报错时，其卡片独立展示错误原因，丝毫不影响其余模型的完成。
- **并排盲测与实时打分**：每个模型一张结果卡，显示回答 Markdown 渲染、完整耗时与 token 指标；支持 1~5 星打分与胜负标记，结果实时入库。
- **历史记录与分类排行榜**：自动归档所有评测轮次，可按分类（Prompt 设计 / RAG / 代码 / 选型）筛选排行榜，计算胜率、平均耗时与 P90 稳定性。
- **极简工程设计**：前端采用原生 Vanilla HTML/CSS/JS，无需打包工具，内嵌自写防 XSS Markdown 解析器，支持内网与离线部署。

## 04 / 验证与真实数据（Result）

在系统上线后，我组织了一场 20 道自拟实战题的对战测试（涵盖 Prompt 设计、RAG 调优、Agent 编排、代码评审、模型选型各 4 题），让 `qwen3.8-max-preview` 与 `deepseek-v4-flash` 进行夜间横向对决。

实测硬核数据如下：

| 评估维度 | qwen3.8-max-preview | deepseek-v4-flash | 结论对比 |
|---|---|---|---|
| **请求成功率** | 20/20，零重试 | 20/20，零重试 | 两模型 20 题均一次成功 |
| **平均耗时** | 25.3s | **12.7s** | flash 耗时缩短约一半 |
| **P90 耗时** | 36.9s | **15.5s** | flash P90 低 21.4s |
| **逐题胜负** | 小胜 3 题 | 小胜 4 题 | 其余 13 题质量平手 |

对战结果显示：在本次实测的 20 道自拟题中，`deepseek-v4-flash` 响应耗时明显更短，且综合回答质量与旗舰模型相当。

## 05 / 经验与选型结论（Notes & Takeaways）

1. **Reasoning Token 的截断陷阱**：
   在对接带有思考链（Reasoning）的推理模型时，`max_tokens` 参数必须预留充足额度（推荐至少 2048 起步）。如果阈值设得过小，模型在思考阶段就耗尽了 token 配额，会导致 HTTP 状态码为 200 但正文输出为空的诡异现象。
2. **轻量架构胜过复杂中间件**：
   对于个人和中小团队的评测工具，不需要搭建复杂的分布式消息队列与重量级数据库。FastAPI 的原生协程池配合 SQLite WAL 模式，已经足以承载数十题并发的高负载。
3. **选型靠事实而非跑分**：
   这场对战本身就是竞技场最好的证明——模型选型不必猜测，用真实的业务测试集跑一场，数据自然给出确定答案。
