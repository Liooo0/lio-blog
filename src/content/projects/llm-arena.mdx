## 为什么做这个

做 AI 应用绕不开一个问题：这个场景到底该用哪个模型？看跑分榜没用，跑分答不了"我的业务题"。我需要一个竞技场：把自己的问题丢进去，让几个模型并排回答，用我的标准打分，让数据说话。

## 功能

- **对比评测** — 输入问题 → 多选模型 → 并发调用，每个模型一张结果卡：Markdown 渲染回答、耗时、token 数；单模型失败不影响其他，卡片显示错误原因
- **打分 + 排行榜** — 每个回答可点 1-5 星，实时入库；排行榜按平均分排序，支持按分类筛选，显示对比次数、平均耗时、出错次数
- **历史记录** — 所有评测可回看：问题、各模型回答、打分详情
- **健康检查** — 页面展示每个模型 API 当前是否可用，点击可刷新

## 技术架构

```
浏览器（原生 HTML/CSS/JS，零构建）
   │  fetch /api/*
   ▼
FastAPI ──► llm_client.py ──► OpenAI 兼容 API
   │          （asyncio.gather 并发，单模型失败隔离）
   └──► SQLite（标准库 sqlite3，无 ORM）
```

- 前端零构建、无 CDN，离线可用；Markdown 渲染是自写的最小渲染器，先转义再渲染防 XSS
- LLM 调用层用 `httpx.AsyncClient` + `asyncio.gather` 并发，支持双通道（海外代理 / 国内直连）切换

## 一夜对战：20 题 × 2 模型

2026-08-04 夜里，我让它跑了一场正式对战：自己出 20 道 AI 应用实战题（prompt 设计 / RAG 调优 / Agent 编排 / 代码评审 / 模型选型各 4 题），qwen3.8-max-preview 对阵 deepseek-v4-flash。

| 指标 | qwen3.8-max-preview | deepseek-v4-flash |
|---|---|---|
| 成功率 | 20/20，零重试 | 20/20，零重试 |
| 平均耗时 | 25.3s | **12.7s** |
| P90 耗时 | 36.9s | 15.5s |
| 逐题质量 | 小胜 3 题 | 小胜 4 题 |

其余 13 题打平，均无错误答案——**质量旗鼓相当，flash 快了近一倍**。

## 选型结论

1. 日常问答、代码评审、批量离线任务 → flash：速度快一倍、质量持平、P90 稳定
2. 复杂方案设计、需要现成模板和检查清单的高价值单答 → qwen：细节密度略高，但要多等一倍时间
3. 两个都是推理模型，`max_tokens` 要给 reasoning token 留空间（建议 2048 起），否则会碰到"HTTP 200 但正文为空"的坑

这场对战本身就是竞技场最好的广告：模型选型不用猜，跑一场就知道。
