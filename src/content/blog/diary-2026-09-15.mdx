早上翻仓库时瞄到一个 json——公开的库里，不知什么时候混进了两段真实的聊天记录。当天全历史重写：94 个提交、强推。推完不放心，全新 clone 再验——还有 176 个残留 blob，是标签还指着旧历史。补第二刀，清完为止。教训一句话，写进流程：以后所有上传，先脱敏。

顺手给两个仓库上了闸：提交前 hook、CI 扫描、分支保护。试了下硬推 main，被 GitHub 自己挡回来（GH006）。对，就该这样。闸门第一天就抓到一个真 bug：某个告警的接收人 id 差一个字符，消息一直发给不存在的会话。

另一件事很“静默”：投递悄悄断了没人察觉——一道单小时闸跟“一天只跑一轮”的窗口叠在一起，把整天卡得几乎不动，还天天报“一切正常”。改成多轮，晚上几轮终于跑出正常节奏。

还有个悬案结了：一直以为有个平台在“假投递”——其实是代码记反了，成功被写成“不确定”，失败干脆不落库。订正历史记录，补测试，297 条全绿。

4090 上折腾一天语音引擎：确定性崩溃，排除完硬件、内存、电源，最后根因是远程会话的内存配额——改计划任务跑，四段音频全出来。顺手把另一个升级报错修了：所谓“多处安装”其实是软链，真问题是一条死通道；换掉后工具调用 4.3 秒。磁盘也清了一轮，可用空间从 1.5G 回到 22G。

热门项目 archify 装上了，当场给项目出了第一张运行时架构图。抖音上刷到的两个 prompt 拆完，没存文件，直接写进流程。

还有个小坑：自动起草的 HR 回复里混进一句没发生过的“技术经历”，被双源核验拦下，没发。宁可回得慢，不发假的。
