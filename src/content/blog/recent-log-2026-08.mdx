## 让另一个 AI 来给我挑刺

job-hunter 用了几个月，一直有个疑案：一些明显对口的岗位，莫名其妙被"公司背调"环节过滤掉了。

我把整个项目复制了一份只读副本，让一个全新的 Agent 进去办案。

它还真翻出来了。`deep_filter.py` 里有一行：

```python
jobs = [...只保留目标公司...] or data
```

精确匹配的结果后面挂了个 `or data`——匹配不到就拿搜索返回的全量数据兜底。搜"云链科技"，结果里混进来六条"云链人力资源"的电话销售岗，画像直接判成"销售公司"，正常 AI 岗当场枪毙。

它先写了个复现脚本把问题钉死，然后顺着 `git log -L` 往前翻，最后翻到当时那次提交。

那个 `or data` 不是故意留的，就是写的时候漏掉了。

改完跑了两个场景，都绿了。修复现在还在副本里，准备再过一遍再合回主线。

这次挺有意思的。自己盯一个项目盯久了，很容易默认某些代码"应该就是这么写的"，换个人看反而容易发现这种东西。

## 手机连电脑

想把手机也接上本机的 Hermes，路上踩了一串坑。

1. 先查了一圈才发现，飞书 bot 本来就是外网通道——websocket 常驻，人在哪都能聊
2. 起 `hermes serve`，手机访问 404。看了提示才知道 serve 是纯后端不带 UI，要用的是 `hermes dashboard --host 0.0.0.0`
3. curl 测登录，cookie 死活不生效。查了半天是 cookie 绑域名——127.0.0.1 登出来的 cookie，对 IP 访问无效。这种坑文档不会写，只能拿头撞

局域网通了之后补外网，选了 Tailscale。brew 装 cask 要 sudo 直接失败；换官网 standalone zip 解压拷进 /Applications。登录链接几分钟就过期，得把 login 进程挂后台再慢慢点链接。最后 `Tailscale ip -4` 吐出 `100.70.53.46`，电脑端算入网了。

手机端还没装，暂停中。回头装上登同一个账号，`http://100.70.53.46:9119` 就是口袋里的 Hermes。

## 给 Codex 搬家

顺手把 codex 从 0.146 升到 0.149，然后把 Hermes 这边 95 个技能全部软链进 `~/.codex/skills`——加分类前缀防撞名，零复制，删掉链接就还原。

DeepSeek 通道实测跑通，19.7k tokens 一个来回。本地 4090 的通道也配好了（LM Studio 新版 `/v1/responses` 协议），就等那台机器开机验证一次。

升级路上照例踩了几个坑：chat 协议被砍了只剩 responses，`lmstudio` 变成保留名不能自定义，profile 得拆成单独的 config.toml。一个个试出来的。
