做 AI 应用的人每天都在面对一个问题：**该用哪个模型？**

测评博主会告诉你"XX 碾压一切"，但做产品的人真正需要的是：我这个场景，用哪个模型，快多少、贵多少、质量差多少。

我给自己搭了个小平台（LLM Arena），用真实对战数据回答这个问题。到目前为止跑了 **63 道题、181 次真实模型调用**。今天分享最核心的一个实验：**Flash 和 Pro，到底差多少？**

## 实验设计

同一批题、同一个 API 通道、同一个 prompt，只差模型档位。

- **10 道题 × 2 个模型**（DeepSeek V4 Flash vs V4 Pro），覆盖代码评审 / 模型选型 / Agent 编排 / RAG 调优 / prompt 设计 5 个方向
- 控制变量：同题同 system prompt、max_tokens 相同、并发 ≤3、全局 ≤2 req/s
- 质量口径：逐题阅读完整回答，判定"小胜 / 打平"

## 结果：质量打平，但速度、token、成本全面拉开

### 耗时与 token

| 指标 | Flash | Pro | 差距 |
|---|---|---|---|
| 平均耗时 | **24.2s** | 38.2s | Flash 快 **58%** |
| P90 耗时 | **36.7s** | 47.6s | Flash 低 11s |
| 平均 token | **1385** | 2233 | Pro 多 **61%** |
| 成功率 | 10/10 | 10/10 | 平 |

### 逐题质量：10 题无一碾压

我逐题读了两边完整回答（每题 800-1900 字）：

- **代码评审**（缓存一致性、提示注入）：覆盖相当，Flash 在 Q02 甚至更全（补了合规角度+修复代码）
- **模型选型**（级联路由、P95<3s 架构）：打平
- **Agent 编排**（并行调用、triage 路由）：Pro 在 Q05 的落地性略好，Flash 在 Q06 覆盖面更全
- **RAG 调优**（query 改写、Text-to-SQL）：打平，Flash 在 Q07 反而更全
- **prompt 设计**（苏格拉底式导师、提示注入防御）：打平，Pro 在 Q09 规则略硬

**结论：10 道题没有任何一道出现质量碾压。** 多数打平，个别题互有胜负。

### 成本换算：不止是官方价差的 3 倍

官方定价（2026-08-17 峰谷计费，空闲时段）：Flash 输出 4.5 元/百万，Pro 13.5 元/百万——标价差 3 倍。

但**实际任务成本差 6 倍**。因为 Pro 生成的 token 更多（平均 2233 vs 1385）：

| | Flash | Pro |
|---|---|---|
| 单题平均 tokens | 1385 | 2233 |
| 估算输出 tokens | ~585 | ~1433 |
| 单题成本（估） | ~0.004 元 | ~0.023 元 |
| **成本倍数** | **1×** | **约 6×** |

这就是为什么**实际成本不能看官方标价，要跟真实任务绑定算**。

## 更大的全景：63 题 × 7 个模型

光对比 Flash vs Pro 还不够——我把两个多月来所有对战数据汇总了：

| 模型 | 成功率 | 平均耗时 | 平均 token | 质量小胜题数 |
|---|---|---|---|---|
| **deepseek-v4-flash** | 30/30 (100%) | **22.4s** | **1351** | 6/30 |
| deepseek-v4-pro | 10/10 (100%) | 38.2s | 2233 | 打平 |
| qwen3.7-max | 29/30 (96.7%) | 46.4s | 1803 | **8/30** |
| glm-5.2 | 30/30 (100%) | 46.4s | 1700 | 5/30 |
| qwen3.8-max-preview | 20/20 (100%) | 25.3s | 1113 | 3/20 |
| deepseek-v4-flash-0731 | 20/20 (100%) | **12.7s** | 1762 | 4/20 |

两个发现：

1. **Flash 质量不输 Pro**——但快 58%、省 61%、成本约 1/6。**生产默认选 Flash，没有悬念。**
2. **qwen3.7-max 单答质量上限最高**（小胜 8/30 题，给决策树/成本模型/注意力窗口实测这类"资深架构师视角"），但慢 2 倍、还有过失败记录。定位：高价值单次复杂方案设计才值得升级。

## 我的选型结论（可复现）

| 场景 | 推荐 | 原因 |
|---|---|---|
| 日常问答 / 客服 | **Flash** | 快 58%、省 61%，质量打平 |
| 结构化抽取 / 批量 | **Flash** | 100% 成功率，高吞吐 |
| 复杂推理 / 深度核验 | **Pro** | 单答深度略优，低频可接受 |
| 高价值复杂方案设计 | **qwen3.7-max** | 质量上限最高，接受 2 倍延迟 |
| 代理抖动降级 | **flash-0731（阿里直连）** | 40/40 零失败，最快 |

**一句话：Flash 是生产默认，Pro 是低频兜底，qwen 旗舰是高价值场景的彩蛋。**

## 为什么这件事值得做

因为"选模型"市场上全是玄学。我在面试时能做的，是打开 [GitHub 仓库](https://github.com/Liooo0/llm-arena)，给他看：

- 63 题 × 181 次调用的完整原始数据（JSON 在 reports/ 下）
- 对战脚本（可复现，自己拉下来能跑）
- 一份正式选型报告（`reports/benchmark-2026-08.md`）

**不是拍脑袋，是数据。而且数据是公开可核验的。**

这也是我给自己 7 个项目定模型分层（Flash 生产默认 / Pro 复杂推理）的依据——不是"我觉得便宜"，是"同一道题质量打平、成本差 6 倍"。
