2026 年 8 月 4 日早上醒来，我收到了这样一份晨报：昨夜派出的 6 个任务，全部完成，0 失败。95分球鞋监控从报废状态复活、房租专家修好了 5 个致命 bug、LLM 竞技场跑完了 20 题模型对战、摄影机位库从 50 扩到 92……而我全程在睡觉。

这篇记录一下这套"夜班系统"是怎么搭的，以及那一夜真实发生了什么——包括两次翻车。

## 系统的组成

先交代角色分工，一共四层：

- **Hermes 军师** — 我造的飞书 AI 助手（本站项目页有介绍）。它负责编排：拆任务、写任务书、派兵、收晨报
- **Claude Code 多窗口并行** — 每个任务是一个独立的 Claude Code 会话，各自占一个项目目录干活，输出重定向到 `~/night-ops/logs/` 留档
- **任务书（BRIEF）** — 每个任务一份，写清楚背景、做什么、验收标准、文件路径，结尾一句"自主执行，不问问题"
- **时间表（timeline.md）** — 军师维护，每行 = 一个任务的完整生命周期：启动时间、完成时间、耗时、结果、用的模型

调度的部分交给 cron：**夜班执行器每晚 22:00 启动**，按当天的任务卡自动派活；**早上 8:00 晨间总结**，把昨夜结果汇总成晨报。第一夜（也就是这一夜）是军师手动派兵试跑，跑通之后执行器接管。

## 翻车一：120 轮截断，靠 resume 续跑

95分监控的核心是逆向 App API 的签名算法，属于最难啃的活。第一轮跑了 43 分钟，Claude Code 会话到达 120 轮工具调用的上限被截断——活干到一半，会话停了。

好在任务本身有状态落盘：已完成的探索、探针脚本、阶段性结论都在项目目录里。处理方式是直接 **resume 续跑**：新会话读现场、接着干，又花约 70 分钟把 HmacSHA256 签名还原出来，79 项测试全绿，微信推送真实发出。

教训：长攻坚任务别指望一轮跑完，让 agent 把中间状态写进文件，截断了也能接力。

## 翻车二：虚假完成，重派 + 自证要求

llm-arena 的夜间对战第一轮更隐蔽：会话"汇报完成"了，但检查发现**没有留下任何输出日志**——报告文件不存在，结果是编的。

处理分两步：重派任务，并且在任务书里加上硬性要求——完成后必须把结果写进指定文件、在会话内给出可验证的证据（文件路径、测试输出、commit 号），最后用中文汇报关键数字。重派之后 90 分钟跑完：20 题 × 2 模型 40/40 成功，报告文件真实落盘，逐条 cat 验证过。

教训：**"完成了"三个字不值钱，证据才值钱。** 验收标准里必须包含可检查的产出物。

## 三条经验

1. **模型分层**。简单任务（脚本、集成、批量生成）丢给 flash——快且便宜；复杂攻坚（逆向、架构设计）才上强模型。这一夜 6 个任务全用 flash 扛下来了，只有 95分签名这种硬骨头原本预留了强模型轮换，实际 flash 也啃下来了。
2. **任务书要点**。每份 BRIEF 都包含：背景（为什么做）、做什么（动词开头）、验收标准（可检查）、关键文件路径、约束条件（"真实数据绝对不许破坏""这个通道不可用，换那个"）、以及"自主执行，不问问题"。写清楚这些，agent 半夜才不需要来问你。
3. **自证要求**。每个任务的验收里都要求会话内自证：测试全绿的输出、commit 号、文件存在性检查。这一夜之所以是 6/6 而不是"看起来 6/6"，就是因为每个完成都是验证过的完成。

## 接下来

夜班执行器从当晚 22:00 起正式接管：任务卡提前写好，cron 到点派兵，8 点晨报照旧。人睡觉，活照干。

这套东西没有什么黑科技，就是把"任务书写清楚、状态落盘、结果自证"三件事做扎实。如果你也想让 AI 帮你上夜班，建议从一个小任务开始——先让它一夜干成一件事，再谈六件。
